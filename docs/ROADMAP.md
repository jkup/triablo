# Roadmap

Human-owned. Agents do not edit this file; they work from `tasks/open/`.

The ordering matters more than the contents. The recurring failure mode in a
project like this is going wide (lots of content, lots of classes) before the
vertical slice actually works — which produces a large amount of plausible code
that has never been run together.

## Phase 1 — Skeleton and gate ✅

No gameplay. Prove the machinery.

- Monorepo, strict TypeScript, no build step
- `npm run verify` and CI running the identical command
- Deterministic seeded RNG, serializable
- Minimal ECS with canonical snapshot hashing
- Content registry with schema validation
- Headless scenario runner, smoke command, golden replays

## Phase 2 — Vertical slice

One of everything, playable end to end, deliberately ugly.

- One class with three skills
- One monster type with basic chase-and-attack AI
- A five-room dungeon from a hand-authored template
- The damage pipeline (the single most important interface in the game)
- One weapon, one armor slot, one affix
- Save and load
- A client that renders it and accepts input

Exit criterion: a human can play it for sixty seconds and a bot can clear it
headlessly.

## Phase 3 — Systems depth

The mechanics that make an ARPG an ARPG. Still narrow on content.

- Affix system with tiers and power budgets
- Status effects and damage-over-time
- Loot tables, rarity tiers, item power scaling
- Procedural dungeon generation from room templates
- Monster AI behaviors, packs, elite modifiers
- Boss encounters with phases
- Character progression, skill tree, respec

## Phase 4 — Content breadth

This is the phase that parallelizes widest. Many agents, one file each.

- 5 classes × ~25 skills
- 60+ monsters across families and biomes
- Hundreds of affixes, dozens of uniques and set items
- Multiple biomes with distinct room template sets
- Difficulty tiers and endgame scaling

## Phase 5 — Client polish

- Inventory, skill tree, character sheet UI
- Visual effects, hit feedback, damage numbers
- Audio
- Controller support
- Settings and accessibility

## Phase 6 — Autonomous loop

The steady state. Nightly balance simulation produces a report; agents open
tasks from the deltas; content and tuning land continuously.

- Bot plays thousands of runs per night
- Tracked metrics over time: clear time, deaths per class, DPS by build, loot
  distribution, build diversity
- Regression alerts when a metric moves without an intended change
